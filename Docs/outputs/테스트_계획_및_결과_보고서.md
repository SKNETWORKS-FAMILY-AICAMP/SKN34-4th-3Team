## 2. 테스트 계획

### 2-1. 테스트 유형

| 유형 | 내용 | 비고 |
| --- | --- | --- |
| 기능 테스트 (수동) | 화면별로 주요 기능의 실제 작동 여부를 확인 | 본 보고서 3절 |
| 성능(속도) 측정 | AI 답변·영수증 판정·사업계획서 작성 흐름의 체감 소요 시간 측정 | 본 보고서 5절 |
| 단위·통합 테스트 | Backend·LLM·Frontend 자동화 테스트 | 본 보고서 6절 |
| LLM·RAG 품질 평가 | 정책 검색·세금 답변·로드맵 답변 품질 지표 평가 | 본 보고서 7절(요약), 상세는 `Docs/reports/` |

### 2-2. 테스트 항목 선정 기준

- `Docs/Design/FUNCTIONAL_SPEC.md`의 **화면 연결 `○`** 기능(살아 있는 화면이 실제로 API를 호출하는 기능)을 대상으로 한다.
- 화면이 연결되지 않은 기능(`✕`)과 죽은 코드로만 연결된 기능(`△`)은 이번 수동 기능 테스트 범위에서 제외한다.
  - 제외: 사업자 유형 진단(FS-09), 세금 정보 관리(FS-10), 청년창업 세액감면 자동판정(FS-13, 호출 화면이 죽은 코드), 지원 자격 확인(FS-20), 공고문 붙여넣기 요약(FS-22의 `POST` 경로), 관리자 기능(FS-24~28, 화면 미구현)

### 2-3. 합격 기준 (결과 표기)

| 표기 | 의미 |
| :-: | --- |
| **O** | PASS — 기대대로 정상 동작 |
| **X** | FAIL — 기대 결과와 다름(결함은 4절 참조) |
| **△** | 부분 동작 / 조건부 / UX 설계 이슈 |
| **-** | 해당 없음(N/A) 또는 이번 범위 제외 |

> 본 수동 기능 테스트는 항목별 세부 재현 절차(입력값 등)를 개별 기록하지 않고 "결과 확인" 수준으로 판정했다. 다만 조치가 필요했던 결함(BUG-001)은 4절에 재현 절차와 원인·조치 내용을 함께 기록했다.

## 4. 발견된 결함

### BUG-001 — 사업계획서 임시저장 실패 (AWS 배포 환경) · **Fixed**

| 항목 | 내용 |
| --- | --- |
| 발생 기능 | FS-29 사업계획서 임시저장, 마이페이지 보관함 |
| 재현 절차 | 운영 사이트 로그인 → 사업계획서 작성 → 기초 정보 일부 입력 → 임시저장 클릭 |
| 기대 결과 | 보관함(`bizplans`)·작성 상태(`bizplan_drafts`) 저장 및 안내 표시 |
| 실제 결과 | `POST /api/bizplan/plans` → **500 Internal Server Error**, "임시저장하지 못했습니다" 표시. 마이페이지 보관함도 목록 로드 실패 |
| 재현 환경 | AWS 배포 환경(기기 무관). 로컬 Docker는 정상(200) |
| 원인 | 운영 DB 전체 교체(`dropdb`→`createdb`→`pg_restore`) 시 덤프 원본에 `bizplans` 테이블이 없어 유실, 교체 후 `db-migrate` 미실행. **코드·배포 파이프라인·`app_extras.sql` 문제 아님** |
| 조치 | 2026-10-01 App EC2에서 `db-migrate` 재실행 → `bizplans` 생성(코드 수정 없음) |
| 재발 방지 | `AWS_DEPLOY_GUIDE.md`에 "DB 교체·복원 후 `db-migrate` 실행", "덤프는 최신 `main` 스키마 DB에서 생성" 추가. 두 EC2 체크아웃을 `main`으로 전환 |
| 상태 | **Fixed** (재검증 완료 — 데스크탑 임시저장 성공) |

## 7. LLM · RAG 품질 평가 요약

수동 기능 테스트와 별개로, LLM 응답 품질을 동일 평가셋(`holdout250`)으로 개선 전·후 측정했다. 상세는 `Docs/reports/06_EVAL_250_COMPARISON.md` 및 관련 보고서 참조.

| 지표 | 개선 전 | 개선 후 | 변화 |
| --- | ---: | ---: | ---: |
| 전체 평가 통과율 | 78.0% | **84.8%** | +6.8%p |
| 정책 검색 재현율(R@5) | 64.3% | **73.0%** | +8.7%p |
| 세금 답변 통과율 | 66.1% | **80.6%** | +14.5%p |
| 로드맵 답변 통과율 | 91.9% | **96.8%** | +4.8%p |
| Guardrail 정확도 | 100% | **100%** | 유지 |

- 세금 Semantic Cache 적용으로 평균 응답 시간 17.69초 → 12.46초(**−29.6%**), 통과율은 유지.
- 평가 통과율은 route·status·block·grounded·필수문구 등 자동 검사 기준이며, 법률 해석·세액 계산의 실제 정확도를 직접 보증하지는 않는다.
