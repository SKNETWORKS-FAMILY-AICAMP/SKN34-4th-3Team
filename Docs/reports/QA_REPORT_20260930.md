## 3. 발견된 결함

### BUG-001

- **제목**: 사업계획서 임시저장 실패 (AWS 배포 환경)
- **발생 기능**: FS-29 사업계획서 초안 생성(임시저장 부속 기능), 마이페이지 사업계획서 보관함
- **재현 절차**:
  1. https://changup-on.kr/ 로그인 후 사업계획서 작성 화면 진입
  2. 기초 정보 일부 입력
  3. 임시저장 버튼 클릭
  4. (같은 원인) 마이페이지 → 사업계획서 탭 진입
- **기대 결과**: 보관함(`bizplans`)과 작성 화면 임시저장(`bizplan_drafts`)에 저장되고 "임시저장했어요 · 마이페이지에서 관리할 수 있어요" 안내 표시. 마이페이지에 보관함 목록 표시
- **실제 결과**:
  - 임시저장: `POST https://changup-on.kr/api/bizplan/plans` → `500 Internal Server Error`, "임시저장하지 못했습니다. 잠시 후 다시 시도해 주세요." 문구 노출. 보관함 저장이 먼저 실패해 `PUT /api/bizplan/draft`는 호출되지 않음
  - 마이페이지: "사업계획서 목록을 불러오지 못했어요. 잠시 후 다시 시도해 주세요." 문구 노출
- **재현 환경**: AWS 배포 환경(기기 무관). 로컬 Docker 환경은 같은 요청이 정상(200) 처리됨. 모바일 PASS(QA-022)는 운영 DB 교체(2026-09-30 21:13 KST) 이전이나 조치 이후에 테스트한 것으로 추정
- **원인**: 운영 DB에 `bizplans` 테이블이 없었음
  - 2026-09-30 20:32 KST: PR #39 배포 시 `db-migrate`가 `bizplans` 생성 (GitHub Actions deploy 로그)
  - 2026-09-30 21:13 KST: Data EC2에서 `dropdb` → `createdb` → `pg_restore latest_full.dump`로 운영 DB 전체 교체. 덤프 원본 DB에 `bizplans`가 없어 테이블 유실 (DB 생성 시각 `PG_VERSION`, Data EC2 셸 history로 확인)
  - 교체 후 `db-migrate`를 실행하지 않아, 보관함 API(`/api/bizplan/plans`)가 없는 테이블에 접근하면서 500 발생
  - 코드, 배포 파이프라인, `DB/app_extras.sql`의 문제는 아님
- **조치**: 2026-10-01 App EC2에서 `docker compose -f docker-compose.app.yml run --rm db-migrate` 재실행 → `bizplans`, `idx_bizplans_user` 생성(exit 0, DBeaver로 확인). 코드 수정·backend 재시작 없음
- **재발 방지**:
  - `Docs/AWS_DEPLOY_GUIDE.md` 7절(데이터 이전)에 "DB 교체·복원 후 App EC2에서 `db-migrate` 실행", "덤프는 최신 `main` 스키마가 적용된 DB에서 생성" 추가
  - 두 EC2의 체크아웃을 `feature/aws`(단일 브랜치 clone)에서 `main`으로 전환. Data EC2는 `dc79443`(9/28) → `863c7dc`로 최신화
- **후속 확인**: 9/30 21:12 KST 이전에 운영 DB에만 있던 데이터(회원, 지출, 서류 등)는 전체 교체로 유실됐을 수 있음. 교체 직전 백업이 Data EC2 `~/ec2_before_replace.dump`에 있어, 필요하면 비교 후 복구
- **상태**: Fixed

### BUG-002

- **제목**: 데스크탑 로그인 간헐적 실패
- **발생 기능**: FS-02 로그인
- **재현 절차**: 데스크탑에서 로그인 시도 (간헐적으로 재현, 고정 재현 절차 미확정)
- **기대 결과**: 정상 로그인 처리
- **실제 결과**: 간헐적으로 로그인 실패. 에러 메시지에 `Backend(:8000)` 문구 표시. 모바일에서는 동일 증상 없이 정상 로그인됨
  - `:8000`은 실제 포트 노출이 아니라 Frontend `LoginModal.jsx`에 고정된 에러 문구임. 401·409를 제외한 모든 실패(네트워크 끊김, 502/504, 500)에서 표시됨
- **재현 환경**: 데스크탑 (간헐적), 모바일은 미재현
- **원인**: 추정 — 테스트 시점에 EC2(백엔드)가 중지 또는 미기동 상태여서 백엔드 연결에 실패한 것으로 보임. 처음 추정한 nginx 프록시 설정 문제는 근거 없음
- **조치**: 에러 문구에서 내부 포트(`:8000`) 제거 (`Frontend/src/components/LoginModal.jsx`)
- **상태**: Open (EC2 기동 상태에서 재검증 필요)

### BUG-003 (UX 설계 이슈)

- **제목**: "AI로 입력 정리하기"를 실행하지 않으면 다음 단계(초안 생성) 진행 불가
- **발생 기능**: FS-29 사업계획서 초안 생성(계획 정리 단계)
- **재현 절차**:
  1. 사업계획서 작성 화면 진입 — 계획 정리 단계
  2. 기초 정보·아이디어 항목을 입력만 하고 "AI로 입력 정리하기" 버튼을 누르지 않음
  3. 다음 단계로 진행 시도
- **기대 결과**: AI 정리는 보조 기능이므로, 실행하지 않아도 입력한 원본 텍스트로 다음 단계(초안 생성) 진행 가능해야 함
- **실제 결과**: "AI로 입력 정리하기"를 실행하지 않으면 다음 단계 버튼이 비활성화(회색)되어 눌리지 않음. 에러 메시지 없이 요청 자체가 발생하지 않음(클라이언트 측에서 막힘)
- **재현 환경**: 데스크탑·모바일 동일하게 재현
- **원인**: 추정 — Frontend에서 다음 단계 버튼의 활성화 조건이 "AI 정리 완료 여부"로 걸려 있는 것으로 보임(코드 확인 필요)
- **조치**: 미조치
- **상태**: Open
- **비고**: AI 정리는 보조·선택 기능 성격이라, 버그보다는 **UX 흐름 설계 검토가 필요한 이슈**로 분류함. 실행하지 않아도 원본 텍스트로 다음 단계 진행이 가능하도록 하는 방향 제안

## 7. 확인 범위 및 한계

- 이번 QA는 데스크탑·모바일 환경에서 화면에 연결된 주요 기능의 작동 여부와 체감 소요 시간을 확인한 결과이며, 전체 기능 명세(FS-01~FS-31) 대비 통과 여부를 보증하는 정식 테스트는 아니다.
- `FUNCTIONAL_SPEC.md` 기준 화면이 연결되지 않은 기능(사업자 유형 진단 FS-09, 세금 정보 관리 FS-10, 세액감면 자동판정 FS-13, 관리자 기능 FS-24~28 등)은 화면 자체가 없어 이번 QA 범위에서 제외했다.
- 각 테스트 항목의 세부 재현 절차(입력값, 테스트 데이터)는 이번 QA에서 항목 단위로 기록하지 않았다. 재현성이 필요한 결함(BUG-001)은 가능한 범위에서 절차를 남겼다.
