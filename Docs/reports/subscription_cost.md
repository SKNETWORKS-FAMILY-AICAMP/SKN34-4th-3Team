# 구독제 기능 · LLM 비용 · 이윤

작성일: 2026-09-21 · 재산정: 2026-09-29 (gpt-6-luna / gpt-5.6-luna 기준)  
대상 코드: `SKN34-4th-3Team` (`llm_client.py`, `LLM/src/core/config.py`, `LLM/src/serving/rag_routes.py`)

이 문서는 **LLM API 원가(변동비)** 만 다룬다. 서버·Postgres·인건비·마케팅은 포함하지 않는다.

> **검증 메모 (2026-09-30)**: §3·§4의 가격·한도·기능표는 `Backend/services/subscription_service.py`의 `PLANS`로 구현. 유저별 플랜은 `user_subscriptions` 테이블(`DB/app_extras.sql`), API는 `GET/PUT /users/me/subscription`, 화면은 마이페이지 › 구독 · 결제(`Frontend/src/pages/MyPage.jsx` `BillingPanel`). **결제는 목업**(즉시 승인)이며 **한도는 표시만** 하고 기능을 차단하지 않는다. 기능 플래그(`plan_access.py`)·`risk_benchmarks` 테이블은 여전히 없다. LLM 호출 근거는 `Backend/core/llm_client.py`, 모델·리랭커 설정은 `LLM/src/core/config.py`에서 확인했다.

## 5. 주의

1. 금액은 **추정**. 토큰 수는 §1.1 코드 설정 기반 가정이며 실측 전. 세금 시맨틱 캐시(`TAX_CACHE_ENABLED`)가 맞으면 세무 상담 원가는 표보다 낮고, 반복 시스템 프롬프트에 캐시 입력($0.01)이 적용되면 입력 원가가 더 내려감.
2. **Vision 모델 설정 미분리**: 현재 코드는 글자 정리와 Vision 재판독 모두 같은 `llm_factory()`(= `LLM_MODEL`)를 씀(`rag_routes.py` `adapter_receipt_ocr`). gpt-5.6-luna를 Vision 전용으로 쓰려면 별도 모델 설정 추가 필요. 분리하지 않으면 Vision도 gpt-6-luna로 호출됨(이미지 입력 지원 여부 확인 필요).
3. gpt-6-luna의 추론 토큰 과금·이미지 토큰 계산 방식은 공식 가격표에 별도 명시 없음. Vision 이미지 1장은 약 1,500토큰으로 가정.
4. Vision 전환율 30%는 가정. 흐린 사진 비중이 높으면 영수증 원가가 최대 2.0원(글자 정리 + Vision 모두 호출)까지 오름.
5. 결제는 mock. 이윤은 "이 가격이면 LLM 변동비를 커버하는가"에 대한 계산이며, 부가세 포함가라면 매출은 구독료의 1/1.1이고 결제 수수료는 별도 차감 필요.
6. 원가 리스크는 **한도 없는 세무 상담**(리랭크 3회)과 **프로 공고상담 무제한**에 집중.
7. 환율 1,400원/USD 가정. 환율 10% 상승 시 원가도 10% 상승.

### 7.2 개선 방안 — 지표 정확도

1. **토큰 실측**: LangSmith에서 `run_name`별 평균 입력·출력 토큰 집계 (`backend_business_plan`, `backend_receipt_ocr_llm`, `backend_receipt_vision` 등) → §1.2 단가 교체. 리랭크 횟수는 `LLM/src/rag/graph.py`의 `rerank_candidates=` 로그로 집계
2. **공고 요약 재분류**: §2 사용자 원가에서 제외, "월 신규 공고 수 × 2.2원" 운영비로 이동
3. **사업계획서 단가 분리**: 기본 초안 / 양식 사용 초안(양식 분석 + ⌈항목 수 ÷ 8⌉회 호출) 2종
4. **§4 기능표 보완**: 영수증 OCR·공제 판정, 사업계획서, 로드맵의 플랜별 제공 범위 추가 (요금제 결정 사항)

### 7.3 개선 방안 — 원가 절감

리랭크가 1회 원가의 45~62% (공고 상담 45% ~ 법령 설명 62%) → 리랭크 호출 수 감소가 최대 레버.

| 방안 | 근거 코드 | 효과 (1회) | 전제 |
|---|---|---|---|
| 세무 2·3홉 리랭크 생략, RRF 상위 결과 사용 | 리랭크 실패 시 대체 경로 이미 존재 (`graph.py` `tax_rrf_docs[: default_top_k]`) | 세무 14.1 → 최대 8.5원 (−40%) | `LLM/evaluation` 홀드아웃 250건으로 정확도 A/B 확인 후 적용 |
| 법령 설명 결과 캐시 | 검색어가 판정·사유·조건 조합으로 결정 (`rag_routes.py` `_legal_basis_query`), 기존 `tax_rag_cache` 테이블 재사용 | 동일 조건 재요청 4.6 → 0원 | 조건 조합 수가 제한적 |
| 세무 시맨틱 캐시 히트율 측정·임계값 조정 | `tax_cache_similarity_threshold=0.95` | 히트율만큼 세무 원가 감소 | 임계값 하향은 오답 캐시 위험 → 평가 후 |
| 프롬프트 캐시 활용 | gpt-6-luna 캐시 입력 $0.01 (90% 할인) | 고정 시스템 프롬프트 부분 입력비 −90% | 프롬프트 앞부분 고정 구조 유지 |

### 7.4 개선 방안 — 수익 구조

| 방안 | 효과 |
|---|---|
| 무료 플랜 세무 상담 월 한도 (예: 20회) | 무료 원가의 66%가 세무 상담(141 / 213원). 헤비 무료 사용자 손실 상한 설정 |
| 프로 공고 상담 공정 사용 한도 — **현재 불필요, 기준만 설정** | 남용 시나리오(공고 상담 월 2,000회)도 흑자(+5,630원). 다른 기능 사용량을 남용 수준으로 둔 채 공고 상담만 늘리면 약 **2,900회**(2,000 + 5,630 ÷ 6.2)부터 적자. 한도를 둔다면 이보다 여유 있는 월 2,500회 수준. 리랭크·모델 단가 인상 시 재산정 |
| 사업계획서를 유료 기능 또는 건당 과금 | 1회 원가가 가장 큰 기능(1세트 21.6원 이상)을 매출과 연결. 영수증 Vision은 1건 기대 원가 1.0원으로 과금 대상 아님 |
| 부가세·결제 수수료 반영 이익표 추가 | 부가세 포함가 기준 실매출 = 구독료 ÷ 1.1 (베이직 9,000원, 프로 26,364원). 수수료율은 PG 확정 후 반영 |
