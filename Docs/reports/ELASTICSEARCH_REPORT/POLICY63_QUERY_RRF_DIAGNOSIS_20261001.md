# 정책 검색 질문 구성 및 RRF 누락 원인 진단

기존 1.0 가중치 평가의 미적중 11문항과 1.3 가중치 실험에서 적중을 잃은 3문항을 조사했다. 라우팅·Cohere·최종 답변 생성은 실행하지 않았다. 저장된 검색어로 Dense 및 Elasticsearch 검색만 실행하고, 실제와 같은 검색 pool 40개·RRF 상수 60·상위 20개 절단을 재구성했다. 순위 원인을 보기 위해 조회한 200개 중 실제 RRF에는 앞의 40개만 사용했다.

**재현 결과:** 14문항 모두 기존 평가의 RRF Top-20 정책 ID 집합과 동일했다. 원본 및 개인화된 문장 2개만 검색에 사용했고, 추가 facet 검색어는 없었다.

## 원인

원문과 개인화 문장마다 Dense·BM25 목록이 하나씩 있어 총 4개 목록의 점수가 합산된다. `1 / (60 + 순위)`가 목록별로 누적되므로, 한 목록에서만 높은 순위인 정답도 여러 목록에 나타나는 문서에 밀릴 수 있다.

- 청년 문화지원 정책 271: 개인화된 BM25에서 2위였지만 다른 목록의 40개 안에는 없어 RRF 52위가 됐다. 점수는 0.01613, 상위 20개 경계 점수는 0.02727이었다.
- 청년 채용 정책 971: 개인화된 Dense에서 9위였지만 다른 목록의 40개 안에는 없어 RRF 52위가 됐다. 점수는 0.01449, 경계 점수는 0.02837이었다.
- 기술컨설팅 정책 957: 개인화 BM25 21위, 원문 BM25 64위로 원문의 검색 pool 밖에 있어 RRF 70위였다.

이는 정책별 중복 청크를 잘못 여러 번 합산하는 오류는 아니다. 서로 다른 검색 목록 간 합의에 점수를 주는 현재 RRF 방식의 결과다. 높은 반복 점수가 반드시 의미상 더 적합한 문서를 뜻하지는 않는다.

검색어에는 `등록된 제 사업자 정보 기준으로 보고`, `조건이 안 맞는 사업까지 볼 시간은 없어서 실제 대상과 지원내용을 먼저 확인` 등의 요청 문구가 남아 있었다. 현재 개인화 문구 제거 목록은 `등록된 내 사업 정보 기준으로` 등을 처리하지만 평가 문항의 `등록된 제 사업자 정보 기준으로` 표현은 포함하지 않는다.

## 판단과 한계

다음 구현 후보로는 검색어의 불필요한 요청 문구를 정리하는 방법이 더 직접적인 근거를 갖는다. 가중치 조정 없이 정답의 검색 순위와 여러 목록에서의 발견을 개선할 여지가 확인됐다.

이는 14문항만 대상으로 공통 문구를 제거한 진단이다. 나머지 문항의 회귀, 실제 다양한 사용자 문장에 대한 일반화, Cohere의 Top-5 선택은 검증하지 않았다. **새로 RRF에 들어온 5문항을 최종 Hit@5 개선으로 계산할 수 없으며, 전체 평가셋의 성능도 추정하지 않는다.** 프로덕션 적용 전에는 조건을 보존하는 문구 정리와 같은 기준의 전체 정책 63문항 평가가 필요하다.
