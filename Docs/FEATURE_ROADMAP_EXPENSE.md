## 1. 창업 로드맵

### 수정 이유
기존 로드맵은 창업 방법을 다루면서도 **근거가 없었습니다.** "고객 20명 인터뷰", "첫 3년 100% 감면" 같은 내용이 어디서 나온 것인지 확인할 수 없었습니다. 그래서 법령과 공공기관 자료로 **목표마다 근거를 보충**했습니다. 이 근거를 바탕으로 옆의 **AI 코치**가 부족한 창업 내용을 채워 주도록 하는 것이 목표입니다.

### 적용 내용
- **7단계 × 5개 = 35개 목표**를 조사한 내용으로 교체했습니다. 근거 없던 숫자 목표와 기간은 삭제했습니다.
- 목표마다 **근거 등급 배지**가 항목 오른쪽에 붙고, 목표를 누르면 근거 설명과 출처 링크가 펼쳐집니다(+/− 표시는 없습니다).
- 한 단계 안에서 **같은 등급끼리 붙여서** 보여줍니다. 순서는 법령 → 공공기관 → 참고 → 방법론 → 미확인입니다.

| 등급 | 의미 | 개수 |
| --- | --- | --- |
| 법령 | 국가법령정보센터 조문으로 확인 | 15 |
| 공공기관 | 정부·공공기관 자료로 확인 | 7 |
| 참고 | 민간 자료 등, 공식 자료로 재확인 필요 | 7 |
| 방법론 | 린 스타트업 등 통용 방법론, 법적 근거 아님 | 4 |
| 미확인 | 근거 미확인, 공고 원문으로 재확인 필요 | 2 |

- **"이 단계 목표"**: 굵은 글씨의 목표 문장이 먼저 나오고, 그 아래에 흐린 글씨로 "이 단계 목표"와 근거 있는 기한(예: 개업일부터 20일 이내)이 나옵니다.
- 순서를 잘못 잡으면 손해가 큰 항목에는 "놓치면 손해", 바뀔 수 있는 숫자에는 기준 시점을 표시했습니다. 화면 아래에는 조사 시점(2026년 9월)과 세무사 확인 안내를 넣었습니다.
- AI 코치는 현재 선택한 단계를 함께 받아 그 단계에 맞게 답하며, 코치의 단계 설명과 키워드도 새 내용에 맞췄습니다.

### 체크리스트
- 목표마다 체크박스가 있어 **현재 창업이 어느 정도 진행되었는지** 점검할 수 있습니다. 전체 진행률과 단계별 완료 표시가 나오고, 마이페이지의 "창업 로드맵 진행률" 카드에도 같은 값이 보입니다.
- 체크한 항목은 글씨가 흐려질 뿐 취소선은 긋지 않습니다. 화면에서 등급순으로 정렬해도 체크 상태는 단계 안의 원래 순번에 묶여 있어 진행률은 그대로입니다.
- 목표 내용을 근거 기반으로 교체하면서 항목이 달라져서, **예전 체크 기록은 이어받지 않고 새로 시작**합니다(저장 키에 버전 `v2`를 붙였습니다).
- 저장 위치는 아직 브라우저(localStorage)입니다. 기기가 바뀌어도 유지하려면 서버 저장이 필요합니다.

### 엔드포인트 · API
로드맵 목표와 체크 상태는 프런트엔드에서 처리해 API 호출이 없고, **AI 코치와 대화 기록만** 서버를 씁니다.

| 구분 | 메서드 · 경로 | 설명 |
| --- | --- | --- |
| Backend | `GET /chat/categories/roadmap/suggested-questions` | 추천 질문 |
| Backend | `POST /chat/messages` | 코치에게 질문 `{question, category:"roadmap", roadmapStep}` |
| Backend | `GET` · `DELETE /chat/messages` | 대화 기록 조회 · 삭제 |
| Backend | `GET /chat/messages/{id}/sources` | 답변 근거 조회 |
| LLM 서비스 | `POST /rag/chat` | Backend가 호출해 코치 응답 생성 |
| 외부 | OpenAI Chat API | 답변 생성 |

법령·공공기관 링크는 새 창으로 여는 **정적 링크**이며 API 호출이 아닙니다.

## 2. 지출관리 (영수증 경비 판정)

### 목적
영수증을 올리면 **지원금 대상인지, 경비 처리가 가능한지** 판단하는 기능입니다. 마이페이지 안에 있던 화면을 **별도 메뉴**로 분리했습니다(전체 메뉴에서 "지출관리" 선택). 이용자의 신뢰를 높이기 위해 결과와 함께 아래 세 가지를 보여줍니다.

1. **어떤 부분을 읽었는지**: 항목별 ✔ 읽음 / ✖ 인식 못 함과 영수증 원문 인용
2. **왜 그렇게 판단했는지**: 단계별 판단 과정
3. **근거 법령**: 조문 번호·제목·요지와 원문 링크

### 읽는 방식: OCR + LLM
글자 읽기와 판단을 나눴습니다.

| 단계 | 역할 |
| --- | --- |
| 1. OCR (Tesseract, 한국어+영어) | 이미지를 먼저 보정한 뒤(EXIF 회전 적용, 흑백·대비 보정, 긴 변 2600px로 축소, 방향이 틀리면 90/270/180도로 돌려 재시도) **글자와 위치, 줄별 인식 신뢰도**를 읽습니다 |
| 2. LLM (OpenAI) | OCR이 읽은 **글자만** 받아 상호·금액·날짜·품목·증빙 종류·지출항목을 정리하고, 읽은 자리의 **원문 글자**를 근거로 돌려줍니다 |

- 이미지를 LLM에 직접 보내던 이전 방식(Vision LLM)보다 같은 이미지에 같은 결과가 나오고, **OCR 인식 신뢰도**를 화면에 보여줄 수 있습니다.
- LLM은 OCR에 없는 글자를 만들지 않고, 뜻을 알 수 없게 깨진 줄(예: `Be: A4SAl`)은 품목에 넣지 않도록 제한했습니다. 못 읽은 값이 기본값(오늘 날짜, 0원 등)에 섞이지 않도록 **읽음 여부를 따로 저장**합니다.
- **대체 경로**: OCR 엔진을 쓸 수 없거나 글자를 거의 못 읽으면(8자 미만) 이전 방식(Vision LLM)으로 대신 읽습니다. 화면에는 어느 방식으로 읽었는지 표시됩니다(`OCR + LLM` / `Vision LLM`).
- OCR은 LLM 서비스 컨테이너 안에서 Tesseract를 실행하는 방식이라 **별도 외부 API 호출이 없습니다.** (`LLM/Dockerfile`에서 설치)

### 처리 흐름
```
화면 → Backend → LLM 서비스 → Tesseract(OCR) → OpenAI(글자 해석)   영수증 읽기
                             └(글자 부족 시) OpenAI(Vision)         대체 경로
화면 → Backend → LLM 서비스 → 세법 검색(RAG)                        판단 근거
Backend ↔ PostgreSQL                                               이미지·결과 저장
```

### 판단 규칙
- **증빙 적격**(소득세법 제160조의2): 세금계산서·카드전표·현금영수증은 금액과 무관하게 적격, 간이영수증은 건당 3만 원 이하만 적격입니다. 부적격이면 증빙불비 가산세(2%) 위험을 안내합니다.
- **3단계 판정**: `높음`(신뢰도 0.7 이상 + 증빙 적격) / `확인 필요` / `어려움`
- **지출항목 9개**: 사무용품, 통신비, 차량유지비, 광고선전비, 임차료, 복리후생비, 접대비, 교육·도서, 기타. LLM이 분류하고 사용자가 드롭다운으로 바꿉니다.
- 세법 자료로 뒷받침된 AI 판정만 규칙 판정을 덮어쓰고, 근거를 못 찾은 응답은 안내 문구로만 씁니다.

### 화면
영수증 카드(썸네일·이름·업로드 시각·금액·지출항목·판정 배지)와, 카드를 펼치면 나오는 접었다 펼 수 있는 세 섹션(📖 읽은 내용 / 🧭 판단 과정 / 📚 세법 근거·관련 법령)으로 구성됩니다. "읽은 내용"에는 읽은 방식과 OCR 인식 신뢰도가 함께 표시됩니다.

### 엔드포인트
모두 로그인 토큰(`Authorization: Bearer ...`)이 필요합니다.

| 메서드 · 경로 | 설명 | 하위 호출 |
| --- | --- | --- |
| `POST /expenses/receipts` | 영수증 등록(이미지 4MB 이하) | LLM `POST /ocr/receipt` |
| `GET /expenses` | 지출 목록 | - |
| `GET /expenses/receipts/{id}` | 추출 결과 | - |
| `GET /expenses/receipts/{id}/image` | 원본 이미지 | - |
| `GET /expenses/{id}/analysis` | 읽은 항목·판단 단계·관련 법령·읽은 방식(즉시 응답) | - |
| `GET /expenses/{id}/deductibility` | 경비 처리 가능성·세법 근거 | LLM `POST /rag/deductibility` |
| `PATCH /expenses/{id}` | 지출항목 변경 후 재판정 | LLM `POST /rag/deductibility` |
| `DELETE /expenses/{id}` | 삭제 | - |

**사용 API**: LLM 서비스(`/ocr/receipt`, `/rag/deductibility`), OpenAI(글자 해석·Vision 대체·임베딩), Cohere Rerank, PostgreSQL. OCR(Tesseract)은 LLM 컨테이너 안에서 실행됩니다. 관련 법령은 국가법령정보센터로 가는 **링크**만 제공합니다.

### 관련 법령
소득세법 제27조·제160조의2(항상), 제81조의6·법인세법 제75조의5(증빙 부적격일 때), 소득세법 제35조·법인세법 제25조(접대비), 소득세법 제33조의2(차량유지비), 소득세법 시행령 제55조(복리후생비·광고선전비)입니다. 조문 번호와 제목은 원문으로 확인했고 요지는 요약입니다.

### 저장 데이터
`DB/app_extras.sql`로 컬럼을 추가하며 `setup.bat`/`setup.sh` 실행 시 자동 적용됩니다: `receipts`(원본 이미지), `receipt_extractions`(증빙 종류, 읽음 여부·원문 근거·OCR 신뢰도), `expenses`(판정, 증빙 적격, 빠진 정보).

## 3. 사업계획서

### 목적
사업 아이디어를 정리하면 AI가 정부 지원사업 심사에서 흔히 쓰는 **PSST(문제인식·실현가능성·성장전략·팀구성)** 구조로 사업계획서 초안을 만들어 주는 기능입니다. 지출관리와 같은 이유로 마이페이지에 두지 않고 **별도 메뉴**로 분리했습니다(전체 메뉴 → "사업계획서").

### 적용 내용 (준비 → AI 설계 → 마무리 3단 구성)
- **준비**: 기초 정보(사업명, 한 줄 소개, 신청하려는 지원사업, **지원사업 공고 양식**, 참고할 내용)와 아이디어 정리(목표 고객, 핵심 문제, 해결 방안, 차별점, 팀 구성)를 입력합니다.
- **AI 설계**: "지원사업 공고 양식"에 공고의 사업계획서 항목 구성(예: "1. 창업아이템 개요 / 2. 개발 동기 및 목적 / 3. 시장분석 및 경쟁력 확보방안")을 붙여넣으면, LLM이 그 항목 제목·개수·순서를 그대로 따라 각 항목의 내용을 채웁니다. **비워두면** 기본 PSST(Problem·Solution·Scale-up·Team) 4항목으로 만듭니다. 로드맵 코치와 같은 방식으로 **검색 없이 한 번의 LLM 호출**로 동작합니다(RAG 미사용). 왼쪽 단계 목록도 생성된 항목 수·제목에 맞춰 그대로 따라 바뀝니다. 생성된 항목은 화면에서 바로 고쳐 쓸 수 있습니다.
- **오른쪽 AI 어시스턴트**: 작성 중인 내용을 참고해 질문에 답하는 채팅창이 항상 떠 있습니다. 세금·지원사업 질문이 들어오면 각각 AI 세무 Assistant·공고지원 AI로 안내하고, 대화 기록은 저장하지 않습니다.
- **마무리**: AI 예비진단이 생성된 항목들을 0~100점으로 채점하고 항목별 강점·보완점을 보여줍니다(실제 심사 결과가 아닌 참고용). 완료 후 초안을 **마크다운(.md) 파일로 다운로드**할 수 있습니다.
- 입력값과 생성된 초안·예비진단 결과는 지출관리·로드맵 체크리스트와 마찬가지로 브라우저(localStorage)에 임시저장됩니다.

### 아직 없는 기능(예정)
- **공고 양식 파일 업로드**: 지금은 공고 양식을 텍스트로 붙여넣는 방식입니다. 공고 첨부파일(한글·PDF)을 그대로 올리면 자동으로 항목을 읽어 오는 기능은 아직 없습니다.
- **한글(HWP)·PDF 다운로드**: 지금은 마크다운(.md)만 지원합니다. 한글·PDF로 받는 기능은 아직 없습니다.

### 엔드포인트
모두 로그인 토큰(`Authorization: Bearer ...`)이 필요합니다.

| 메서드 · 경로 | 설명 | 하위 호출 |
| --- | --- | --- |
| `POST /bizplan/generate` | 기초 정보·아이디어로 PSST 초안 생성 | LLM `POST /rag/business-plan` |
| `POST /bizplan/evaluate` | 작성된 PSST 초안 예비진단(점수·강점·보완점) | LLM `POST /rag/business-plan-evaluate` |
| `POST /bizplan/coach` | 아이디어 어시스턴트 질문·답변(대화 기록 미저장) | LLM `POST /rag/business-plan-coach` |

**사용 API**: LLM 서비스(`/rag/business-plan`, `/rag/business-plan-evaluate`, `/rag/business-plan-coach`), OpenAI(초안·채점·어시스턴트 응답 생성). 로드맵 코치와 마찬가지로 지출관리·정책 탐색이 쓰는 공용 RAG 그래프를 거치지 않는 독립된 단일 LLM 호출입니다.

**알아둘 점**
- **OCR 정확도**: 휴대폰 사진은 EXIF 회전 정보만 있고 실제 픽셀은 옆으로 누워 있는 경우가 많아, 보정 없이는 신뢰도가 39% 수준으로 떨어지고 아무것도 읽지 못했습니다. 이미지 보정을 넣어 같은 사진이 신뢰도 60%로 올라 날짜·금액·증빙 종류를 읽게 됐습니다. 그래도 Tesseract는 흐린 사진, 심하게 기울어진 사진, 작은 글씨, 손글씨에서 오인식이 늘어납니다. 그런 줄은 신뢰도가 낮게 표시되고 LLM이 추측해서 채우지 않으므로 **못 읽은 값이 "인식 못 함"으로 남을 수 있습니다.** 실제 영수증 사진으로 정확도를 검증하고, 부족하면 이미지 보정(확대·대비)이나 다른 OCR 엔진 도입을 검토합니다.
- **세법 조문 데이터**: 로컬 DB의 `tax_documents`가 비어 있으면 "AI가 찾은 세법 자료"가 비고 판정은 규칙 기반으로만 나옵니다. 조문은 `DB/scripts/02_collect_tax_law.py`로 채웁니다.
- **LLM 이미지 재빌드**: OCR을 위해 `LLM/Dockerfile`에 Tesseract를 추가했으므로, 처음 한 번은 `setup.bat`/`setup.sh`(또는 `docker compose build llm`)로 이미지를 다시 빌드해야 합니다.
- 로드맵의 "미확인" 2건과 일부 숫자(노란우산공제 구간, 청년창업 감면율)는 원문 대조가 필요하고, 일부 법령 링크는 주소 규칙으로 만든 것이라 열어서 확인해야 합니다.
- 모든 법령 요지와 판정은 참고용이며 최종 판단은 세무사 확인이 필요합니다.
