# 창업 로드맵 · 지출관리 · 사업계획서 기능 정리

창업ON의 세 가지 기능을 처음 보는 사람도 이해할 수 있게 정리한 문서입니다.

| 기능 | 한 줄 설명 | 상태 |
| --- | --- | --- |
| **창업 로드맵** | 창업 단계별 할 일을 **근거(법령·공공자료)와 함께** 보여주고 체크리스트로 진행률을 관리 | 완료 |
| **지출관리** | 영수증 사진을 올리면 **경비 처리가 되는지** 판단하고, 판단 이유와 근거 법령을 보여줌 | 완료 (지원금 대상 판정은 예정) |
| **사업계획서** | 아이디어를 입력하면 AI가 **정부 지원사업 양식에 맞춘 사업계획서 초안**을 써 주고 점수를 매겨 줌 | 완료 (양식 파일 업로드, 한글·PDF 다운로드는 예정) |

> 공통 원칙: AI가 답을 내놓을 때 **"왜 그런지"와 "근거가 무엇인지"를 같이 보여준다.** 모든 판단은 참고용이며, 세금 관련 최종 판단은 세무사 확인이 필요합니다.

## 1. 창업 로드맵

**무엇을 하나요?**
창업을 7단계로 나누고, 단계마다 해야 할 목표 5개(총 35개)를 보여줍니다. 오른쪽의 AI 코치에게 지금 단계에 대해 질문할 수 있습니다.

**왜 바꿨나요?**
예전 로드맵에는 "고객 20명 인터뷰" 같은 목표가 있었지만 **어디서 나온 숫자인지 알 수 없었습니다.** 그래서 목표마다 근거를 찾아 붙이고, 근거가 없는 숫자는 뺐습니다.

**근거 등급** — 목표 옆 배지로 표시되고, 누르면 근거 설명과 출처 링크가 펼쳐집니다.

| 등급 | 의미 | 개수 |
| --- | --- | --- |
| 법령 | 법 조문으로 확인됨 | 15 |
| 공공기관 | 정부·공공기관 자료로 확인됨 | 7 |
| 참고 | 민간 자료라 재확인 필요 | 7 |
| 방법론 | 린 스타트업 같은 통용 방법론(법적 근거 아님) | 4 |
| 미확인 | 근거를 못 찾음, 원문 확인 필요 | 2 |

**체크리스트**
- 목표마다 체크박스가 있어 전체·단계별 진행률을 보여주고, 마이페이지에도 같은 진행률이 나옵니다.
- 지금은 **브라우저에만 저장**되어 다른 기기에서는 보이지 않습니다(서버 저장은 예정).

**엔드포인트 · API**
로드맵 목표와 체크 상태는 화면(프런트엔드)에서만 처리해 API 호출이 없고, **AI 코치와 대화 기록만** 서버를 씁니다.

| 구분 | 메서드 · 경로 | 설명 |
| --- | --- | --- |
| Backend | `GET /chat/categories/roadmap/suggested-questions` | 추천 질문 목록 (로그인 불필요) |
| Backend | `POST /chat/messages` | AI 코치에게 질문 `{question, category: "roadmap", roadmapStep}` |
| Backend | `GET /chat/messages` · `DELETE /chat/messages` | 대화 기록 조회 · 삭제 |
| Backend | `GET /chat/messages/{id}/sources` | 답변 근거 문서 조회 |
| LLM 서비스 | `POST /rag/chat` | Backend가 호출해 코치 답변 생성 |
| 외부 API | OpenAI Chat API | 답변 생성 |

법령·공공기관 링크는 새 창으로 여는 **일반 링크**라 API 호출이 아닙니다.

## 2. 지출관리 (영수증 경비 판정)

**무엇을 하나요?**
영수증 사진을 올리면 상호·금액·날짜·품목을 읽고, **이 지출을 사업 경비로 처리할 수 있는지** 판단합니다. 결과와 함께 세 가지를 보여줍니다.

1. **무엇을 읽었는지** — 항목별로 읽음/인식 못 함과 영수증 원문
2. **왜 그렇게 판단했는지** — 단계별 판단 과정
3. **근거 법령** — 관련 세법 조문과 원문 링크

**어떻게 읽나요? (OCR + LLM)**
글자를 읽는 일과 해석하는 일을 나눴습니다.

```
영수증 사진 → ① OCR(Tesseract): 사진에서 글자만 읽음
            → ② LLM(OpenAI): 읽은 글자를 보고 상호·금액·품목 등을 정리
            → ③ 세법 검색(RAG): 관련 세법 자료를 찾아 경비 처리 가능성 판단
```

- **OCR**: 사진 속 글자를 텍스트로 바꾸는 기술. 무료 오픈소스인 Tesseract를 서버 안에서 돌려 외부 API 비용이 없습니다.
- **LLM은 OCR이 읽은 글자만 씁니다.** 없는 글자를 지어내지 않고, 못 읽은 값은 "인식 못 함"으로 남깁니다.
- 글자를 거의 못 읽은 경우에만 사진을 AI에게 직접 보여주는 방식(Vision)으로 대신 읽습니다.

**OCR 엔진, 왜 Tesseract를 쓰나요? (비교 실험)**
휴대폰 사진은 인식률이 낮아지는 문제가 있어, 무료로 쓸 수 있는 대체 엔진 4종을 검토했습니다.

| 엔진 | 특징 | 판단 |
| --- | --- | --- |
| **Tesseract**(현재) | 시스템 패키지만 설치, 용량 부담 없음 | 채택 |
| PaddleOCR | GPU 없이도 설치 가능한 유일한 후보 | 실측 후 보류 |
| EasyOCR / Surya / docTR | PyTorch 기반이라 CPU 서버인데도 NVIDIA CUDA 라이브러리가 딸려 와 이미지가 수 GB 늘어남 | 제외 |

**PaddleOCR 실측 결과** (같은 영수증 사진으로 비교)

| 항목 | Tesseract(현재) | PaddleOCR |
| --- | --- | --- |
| 처리 시간 | **2.4초** | **27~28초** (약 11배 느림) |
| 평균 신뢰도 | 57.9% | 58~63% |
| 한글 인식 | 한글로 정상 인식 | 한글이 **중국어로 깨짐** |
| 서버 이미지 용량 | 1.24GB | 4.33GB (**+3GB**) |

조사 단계에서는 PaddleOCR이 유력해 보였지만, 실제로 설치해 재보니 **속도·정확도·용량 모두 기존 Tesseract가 더 나은 것**으로 나와 도입을 보류했습니다.

**전처리 개선 실험** — 엔진을 바꾸는 대신 Tesseract의 이미지 전처리를 다시 맞췄습니다.
- 이미지 축소 기준을 2600px → 2000px로 낮춤(글자가 너무 크면 배경 노이즈까지 또렷해져 오히려 방해됨)
- 점 노이즈 제거(median filter) + 획 선명화(unsharp mask) 추가
- 보정 강도가 다른 두 버전을 각각 읽어 더 잘 읽힌 쪽을 채택(사진마다 유리한 쪽이 달라서)
- Otsu 이진화, 방향 자동 판별(OSD)도 같이 실험했지만 오히려 정확도가 떨어지거나 오판이 있어 제외

**추가 개선 3건 (2026-09-24, 적용 완료)** — 실제 사용자가 올린 영수증에서 인식이 아예 안 되는 사례가 나와 추가로 손봤습니다.

1. **방향(회전) 판정 버그 수정**: 사진을 0/90/180/270도로 돌려 가며 어느 방향이 맞는지 점수를 매기는데, 신뢰도가 낮은 줄까지 전부 점수에 더하고 있었습니다. 글자가 옆으로 누우면 뜻 없는 글자가 수백 자 쏟아지는데, 이걸 다 더하면 **오히려 틀린 방향이 점수가 더 높게** 나왔습니다. → 신뢰도 60% 미만 줄은 점수에서 빼도록 수정.
2. **지역 적응형 이진화 추가**: 감열지 영수증은 위아래 밝기가 고르지 않은데, 기존 두 전처리(대비 보정, 노이즈 제거+선명화)는 사진 전체에 같은 기준을 씁니다. 칸(35px)마다 그 주변 평균 밝기를 기준으로 흑백을 나누는 방식을 세 번째 후보로 추가했습니다. 조명이 나쁜 사진에서 효과가 커, 밝기가 고르지 않은 사진 2장에서 **유효 글자 수가 93→313자, 198→226자**로 늘었고, 방향 재시도 없이 0도에서 바로 통과해 **처리 시간이 19.5초→7.9초**로 줄었습니다.
3. **Vision 대체 안전장치**: OCR 글자가 충분해 보여도(글자 수 기준은 통과) 날짜·상호·금액을 하나도 못 채우면, 사진을 AI가 직접 보는 Vision 방식으로 한 번 더 읽도록 했습니다. 예전에는 이런 경우 세 필드 모두 "인식 못 함"으로 끝났습니다.

**최종 성능** (실제 영수증 6장, 이번 세션의 모든 개선 적용 전 → 후)

| 지표 | 개선 전 | 개선 후 |
| --- | --- | --- |
| 유효 인식 글자 수 | 739자 | **1,064자 (+44%)** |
| 처리 시간 합계 | 28.5초 | **20.6초 (−28%)** |
| 조명이 나쁜 사진 1장 | 0/5개 필드 인식(93자, 19.5초) | **5/5개 필드 인식(313자, 7.9초)** |

지역 적응형 이진화가 `_score`(신뢰도 가중 글자 수) 기준으로는 더 좋게 나왔는데도 "신뢰도 70% 이상 글자 수"만 보면 줄어드는 사진(1건)이 있었습니다. 실제 LLM 추출 결과를 직접 비교해 보니 품목을 2개→3개 더 잡아 **표시 지표보다 실제 결과가 더 나은 경우**였습니다. 벤치마크 지표 하나만으로 성능을 판단하지 않고, 최종 산출물(LLM이 뽑은 값)로 다시 확인하는 게 안전합니다.

**어떻게 판단하나요?**
- **증빙 인정 여부**: 세금계산서·카드전표·현금영수증은 금액과 상관없이 인정되고, 간이영수증은 3만 원 이하만 인정됩니다(소득세법 제160조의2).
- **판정 3단계**: `높음` / `확인 필요` / `어려움`
- **지출항목 9개**(사무용품, 통신비, 차량유지비, 광고선전비, 임차료, 복리후생비, 접대비, 교육·도서, 기타)는 AI가 먼저 분류하고, 사용자가 드롭다운으로 바꿀 수 있습니다.

**화면에서 할 수 있는 것**
- 영수증 카드 목록(썸네일·상호·거래일·금액·지출항목·판정)
- 카드를 펼치면 읽은 내용 / 판단 과정 / 세법 근거를 볼 수 있음
- 품목별 금액 표, OCR이 놓친 품목 직접 추가, 상호 직접 수정
- 통계·필터·검색, 엑셀 다운로드

**알아둘 점**
- 흐리거나 기울어진 사진, 작은 글씨, 손글씨는 잘 못 읽을 수 있습니다. 이 경우 AI가 추측해서 채우지 않고 "인식 못 함"으로 남깁니다.
- 로컬 DB에 세법 데이터(`tax_documents`)가 없으면 AI 판정 없이 규칙 기반 판정만 나옵니다. `DB/scripts/02_collect_tax_law.py`로 채울 수 있습니다.

## 3. 사업계획서

**무엇을 하나요?**
사업 아이디어를 입력하면 AI가 사업계획서 초안을 써 주고, 예비 점수를 매겨 줍니다. 화면은 **준비 → AI 설계 → 마무리** 3단계입니다.

| 단계 | 하는 일 |
| --- | --- |
| **준비** | 사업명, 한 줄 소개, 목표 고객, 해결하려는 문제, 차별점, 팀 구성 등을 입력 |
| **AI 설계** | AI가 초안을 작성. 결과는 화면에서 바로 고쳐 쓸 수 있음 |
| **마무리** | AI가 0~100점으로 채점하고 항목별 강점·보완점을 알려줌. 초안은 .md 파일로 다운로드 |

**어떤 양식으로 쓰나요?**
- **기본값은 PSST** — 정부 지원사업 심사에서 흔히 쓰는 4항목 구조입니다: Problem(문제인식) · Solution(실현가능성) · Scale-up(성장전략) · Team(팀 구성).
- **지원하려는 공고의 양식 목차를 붙여넣으면** 그 항목 제목·순서를 그대로 따라 작성합니다. (예: "1. 창업아이템 개요 / 2. 개발 동기 / 3. 시장분석")

**오른쪽 AI 어시스턴트**
작성 중인 내용을 참고해 질문에 답해 주는 채팅창입니다. 세금·지원사업 질문은 해당 전용 AI 메뉴로 안내합니다. 대화 기록은 저장하지 않습니다.

입력한 내용과 초안은 브라우저에 임시 저장됩니다.

**엔드포인트 · API**
Backend API는 모두 로그인 토큰(`Authorization: Bearer ...`)이 필요합니다.

| 메서드 · 경로 | 설명 | 내부에서 호출하는 LLM 서비스 |
| --- | --- | --- |
| `POST /bizplan/generate` | 입력한 정보로 사업계획서 초안 생성 | `POST /rag/business-plan` |
| `POST /bizplan/evaluate` | 초안 예비진단 (점수·강점·보완점) | `POST /rag/business-plan-evaluate` |
| `POST /bizplan/coach` | AI 어시스턴트 질문·답변 (기록 미저장) | `POST /rag/business-plan-coach` |

**사용하는 API·서비스**

| 구분 | 이름 | 용도 |
| --- | --- | --- |
| LLM 서비스(자체) | `/rag/business-plan`, `/rag/business-plan-evaluate`, `/rag/business-plan-coach` | 초안 작성, 채점, 어시스턴트 |
| 외부 API | OpenAI | 초안·채점·어시스턴트 답변 생성 |

로드맵 코치처럼 **세법 검색(RAG) 없이 한 번의 LLM 호출**로 동작합니다.
