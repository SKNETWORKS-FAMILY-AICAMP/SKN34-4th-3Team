## 1. 창업 로드맵

### 수정 이유
기존 로드맵은 창업 방법을 다루면서도 **근거가 없었습니다.** "고객 20명 인터뷰", "첫 3년 100% 감면" 같은 내용이 어디서 나온 것인지 확인할 수 없었습니다. 그래서 법령과 공공기관 자료로 **목표마다 근거를 보충**했습니다. 이 근거를 바탕으로 옆의 **AI 코치**가 부족한 창업 내용을 채워 주도록 하는 것이 목표입니다.

### 적용 내용
- **7단계 × 5개 = 35개 목표**를 조사한 내용으로 교체했습니다. 근거 없던 숫자 목표와 기간은 삭제했습니다.
- 목표마다 **근거 등급 배지**를 붙이고, 누르면 근거 설명과 출처 링크가 펼쳐집니다.

| 등급 | 의미 | 개수 |
| --- | --- | --- |
| 법령 | 국가법령정보센터 조문으로 확인 | 15 |
| 공공기관 | 정부·공공기관 자료로 확인 | 7 |
| 참고 | 민간 자료 등, 공식 자료로 재확인 필요 | 7 |
| 방법론 | 린 스타트업 등 통용 방법론, 법적 근거 아님 | 4 |
| 미확인 | 근거 미확인, 공고 원문으로 재확인 필요 | 2 |

- 순서를 잘못 잡으면 손해가 큰 항목에는 "놓치면 손해", 바뀔 수 있는 숫자에는 기준 시점을 표시했습니다. 화면 아래에는 조사 시점(2026년 9월)과 세무사 확인 안내를 넣었습니다.
- AI 코치는 현재 선택한 단계를 함께 받아 그 단계에 맞게 답하며, 코치의 단계 설명과 키워드도 새 내용에 맞췄습니다.
- **체크리스트**는 이번에 제거했고, 현재 창업 진행 정도를 점검하는 기능으로 **다시 넣을 예정**입니다. 기기가 바뀌어도 유지하려면 서버 저장이 필요합니다.

### 엔드포인트 · API
로드맵 목표는 프런트엔드 상수라 API 호출이 없고, **AI 코치와 대화 기록만** 서버를 씁니다.

| 구분 | 메서드 · 경로 | 설명 |
| --- | --- | --- |
| Backend | `GET /chat/categories/roadmap/suggested-questions` | 추천 질문 |
| Backend | `POST /chat/messages` | 코치에게 질문 `{question, category:"roadmap", roadmapStep}` |
| Backend | `GET` · `DELETE /chat/messages` | 대화 기록 조회 · 삭제 |
| Backend | `GET /chat/messages/{id}/sources` | 답변 근거 조회 |
| LLM 서비스 | `POST /rag/chat` | Backend가 호출해 코치 응답 생성 |
| 외부 | OpenAI Chat API | 답변 생성 |

법령·공공기관 링크는 새 창으로 여는 **정적 링크**이며 API 호출이 아닙니다.

## 2. 지출관리 (영수증 경비 판정)

### 목적
영수증을 올리면 **지원금 대상인지, 경비 처리가 가능한지** 판단하는 기능입니다. 현재는 마이페이지 안에 있고 이후 **별도 메뉴로 분리**할 계획입니다. 이용자의 신뢰를 높이기 위해 결과와 함께 아래 세 가지를 보여줍니다.

1. **어떤 부분을 읽었는지**: 항목별 ✔ 읽음 / ✖ 인식 못 함과 영수증 원문 인용
2. **왜 그렇게 판단했는지**: 단계별 판단 과정
3. **근거 법령**: 조문 번호·제목·요지와 원문 링크

### 읽는 방식

**현재: LLM 방식(Vision LLM)** — OCR 엔진 없이 **Vision LLM**(OpenAI)이 이미지를 직접 보고 값을 채웁니다. 읽은 **원문 글자**를 함께 받아 근거로 보여주고, 못 읽은 값이 기본값(오늘 날짜, 0원 등)에 섞이지 않도록 **읽음 여부를 따로 저장**합니다. 다만 글자 좌표와 글자별 신뢰도는 제공되지 않고, 같은 이미지라도 결과가 달라질 수 있습니다.

**변경 예정: OCR + LLM 방식** — 글자 읽기와 판단을 나눕니다.

| 단계 | 역할 | 기대 효과 |
| --- | --- | --- |
| 1. OCR | 영수증에서 **글자와 위치(좌표)** 를 읽어 냅니다 | 같은 이미지는 같은 결과가 나오고, 읽은 위치를 영수증 위에 표시할 수 있습니다 |
| 2. LLM | OCR이 읽은 글자를 해석해 상호·금액·증빙 종류·지출항목을 정리하고 판단 이유와 근거 법령을 설명합니다 | 이미지가 아니라 글자만 보내므로 지어낼 여지가 줄고 비용도 줄어듭니다 |

- 이렇게 바꾸면 "영수증의 **어느 부분**을 읽었는지"를 좌표로 보여줄 수 있어 신뢰를 더 높일 수 있습니다.
- OCR 엔진은 아직 정해지지 않았고, 정확도와 비용을 비교해 선정할 예정입니다.
- 지금의 `POST /ocr/receipt` 창구는 그대로 두고 내부 구현만 바꾸는 방식을 우선 검토합니다. 그러면 Backend와 화면은 수정이 적습니다.

### 처리 흐름
```
[현재]     화면 → Backend → LLM 서비스 → OpenAI(Vision)          영수증 읽기
[변경 예정] 화면 → Backend → LLM 서비스 → OCR → LLM(글자 해석)     영수증 읽기
화면 → Backend → LLM 서비스 → 세법 검색(RAG)                      판단 근거
Backend ↔ PostgreSQL                                              이미지·결과 저장
```

### 판단 규칙
- **증빙 적격**(소득세법 제160조의2): 세금계산서·카드전표·현금영수증은 금액과 무관하게 적격, 간이영수증은 건당 3만 원 이하만 적격입니다. 부적격이면 증빙불비 가산세(2%) 위험을 안내합니다.
- **3단계 판정**: `높음`(신뢰도 0.7 이상 + 증빙 적격) / `애매함` / `어려움`
- **지출항목 9개**: 사무용품, 통신비, 차량유지비, 광고선전비, 임차료, 복리후생비, 접대비, 교육·도서, 기타. OCR이 분류하고 사용자가 드롭다운으로 바꿉니다.
- 세법 자료로 뒷받침된 AI 판정만 규칙 판정을 덮어쓰고, 근거를 못 찾은 응답은 안내 문구로만 씁니다.

### 화면
영수증 카드(썸네일·이름·업로드 시각·금액·지출항목·판정 배지)와, 카드를 펼치면 나오는 접었다 펼 수 있는 세 섹션(📖 읽은 내용 / 🧭 판단 과정 / 📚 세법 근거·관련 법령)으로 구성됩니다.

### 엔드포인트
모두 로그인 토큰(`Authorization: Bearer ...`)이 필요합니다.

| 메서드 · 경로 | 설명 | 하위 호출 |
| --- | --- | --- |
| `POST /expenses/receipts` | 영수증 등록(이미지 4MB 이하) | LLM `POST /ocr/receipt` |
| `GET /expenses` | 지출 목록 | - |
| `GET /expenses/receipts/{id}` | 추출 결과 | - |
| `GET /expenses/receipts/{id}/image` | 원본 이미지 | - |
| `GET /expenses/{id}/analysis` | 읽은 항목·판단 단계·관련 법령(즉시 응답) | - |
| `GET /expenses/{id}/deductibility` | 경비 처리 가능성·세법 근거 | LLM `POST /rag/deductibility` |
| `PATCH /expenses/{id}` | 지출항목 변경 후 재판정 | LLM `POST /rag/deductibility` |
| `DELETE /expenses/{id}` | 삭제 | - |

**사용 API**: LLM 서비스(`/ocr/receipt`, `/rag/deductibility`), OpenAI(Vision·임베딩), Cohere Rerank, PostgreSQL. 관련 법령은 국가법령정보센터로 가는 **링크**만 제공합니다.

**변경 예정 시 달라지는 점**: 영수증 읽기가 "OpenAI Vision 한 번"에서 "**OCR 엔진 호출 → OpenAI(글자 해석)**"로 바뀝니다. OCR 엔진은 선정 후 이 목록에 추가합니다.

### 관련 법령
소득세법 제27조·제160조의2(항상), 제81조의6·법인세법 제75조의5(증빙 부적격일 때), 소득세법 제35조·법인세법 제25조(접대비), 소득세법 제33조의2(차량유지비), 소득세법 시행령 제55조(복리후생비·광고선전비)입니다. 조문 번호와 제목은 원문으로 확인했고 요지는 요약입니다.

### 저장 데이터
`DB/app_extras.sql`로 컬럼을 추가하며 `setup.bat`/`setup.sh` 실행 시 자동 적용됩니다: `receipts`(원본 이미지), `receipt_extractions`(증빙 종류, 읽음 여부·원문 근거), `expenses`(판정, 증빙 적격, 빠진 정보).

**알아둘 점**
- 로컬 DB의 세법 조문(`tax_documents`)이 비어 있으면 "AI가 찾은 세법 자료"가 비고 판정은 규칙 기반으로만 나옵니다. 조문은 `DB/scripts/02_collect_tax_law.py`로 채웁니다.
- 화면과 코드의 "OCR"이라는 표현은 현재 Vision LLM을 가리킵니다. OCR + LLM으로 바꾸면 그때부터 실제 OCR이 됩니다.
- 로드맵의 "미확인" 2건과 일부 숫자(노란우산공제 구간, 청년창업 감면율)는 원문 대조가 필요하고, 일부 법령 링크는 주소 규칙으로 만든 것이라 열어서 확인해야 합니다.
- 모든 법령 요지와 판정은 참고용이며 최종 판단은 세무사 확인이 필요합니다.
